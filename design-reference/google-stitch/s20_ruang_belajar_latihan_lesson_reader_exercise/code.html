1.3: State Transitions & Finite State Machines

Membaca (Est. 18m)
Progres: Langkah 2 dari 3
Architecture Design SE-FND-M01-L03

Representasi Transisi Keadaan (State Transitions) dalam Rekayasa Perangkat Lunak

Bagaimana menstrukturkan sistem backend yang deterministik dan tahan kegagalan dengan pemodelan mesin keadaan berhingga (Finite State Machine).

1. Masalah Anti-Pattern: Primitive Boolean Explosion

Pada sistem perangkat lunak yang berkembang cepat, status entitas sering kali dimulai secara naif menggunakan pasangan boolean flags: is_pending, is_verified, dan is_cancelled. Seiring berjalannya waktu, kombinasi variabel flag ini menghasilkan keadaan tak terdefinisi (undefined states) seperti status transaksi yang secara bersamaan berstatus verified = true sekaligus cancelled = true.

Dalam paradigma Finite State Machine (FSM), sebuah entitas secara matematis hanya diizinkan berada pada tepat satu status dari sekumpulan status terbatas pada waktu tertentu. Setiap perpindahan status mensyaratkan pemicu (event) dan validasi guard yang eksplisit.

Perhatikan cabang terminal: Dari keadaan PROCESSING, entitas diwajibkan memilih salah satu percabangan strictly typed tanpa ada celah status mengambang.

2. Pola Penulisan FSM Idiomatis di Go

Gunakan konstanta bertipe kustom (typed string atau iota) dengan method receiver untuk memvalidasi peralihan keadaan secara terenkapsulasi sebelum mutasi database dilakukan:

fsm_order_state.go 
01package core_domain
02
03import "fmt"
04
05// OrderState merepresentasikan status deterministik pesanan
06type OrderState string
07
08const (
09    StateCreated   OrderState = "CREATED"
10    StatePaid      OrderState = "PAID"
11    StateShipped   OrderState = "SHIPPED"
12    StateCancelled OrderState = "CANCELLED"
13)
14
15func (s OrderState) CanTransitionTo(target OrderState) bool {
16    switch s {
17    case StateCreated:
18        return target == StatePaid || target == StateCancelled
19    case StatePaid:
20        return target == StateShipped || target == StateCancelled
21    default:
22        return false // Terminal states cannot mutate
23    }
24}

Prinsip Rekayasa Kritis: No Hidden Boolean Flags

Hindari state machine implisit berbasis boolean flags yang bertumpuk; selalu gunakan finite enum state yang eksplisit dengan transisi satu arah yang terdokumentasi dan dapat diaudit secara menyeluruh.

Kunci Solusi & Penjelasan Formal (Gate L03)

Kunci solusi dan rasional desain sengaja disembunyikan untuk mendorong pemahaman mandiri secara mendalam.

Solusi Referensi Arsitektur: 
func (s OrderState) ValidNext() []OrderState {
    switch s {
    case StateCreated:
        return []OrderState{StatePaid, StateCancelled}
    case StatePaid:
        return []OrderState{StateShipped, StateCancelled}
    case StateShipped:
        return []OrderState{} // Terminal! No cancellation allowed.
    case StateCancelled:
        return []OrderState{} // Terminal!
    }
    return nil
}
Rasional Evaluasi: Penguncian status StateShipped adalah prinsip integritas logistik—sekali barang dikirim, pembatalan sistem harus melalui alur kompensasi terpisah (Reverse Logistics / Return Request).
