ADR-014: Deterministic State Machine untuk Order Lifecycle

verified_user Farhan (Lead Architect)
•
schedule Terakhir diedit: 14 Nov 2026, 11:20 WIB

visibility 12 Peninjau
840 kata

1. Konteks & Latar Belakang Masalah

SEC-01

Pada sistem kasir multi-outlet offline GrowPOS Engine, transaksi pemesanan dapat dibuat, diubah, dan dimutasi secara lokal saat koneksi internet toko terputus. Ketika sinkronisasi kembali dijalankan ke kluster pusat, timbul race condition di mana event perubahan status order saling tumpang tindih.

warning

Skenario kegagalan nyata: Status order berstatus PAID dikirim bersamaan dengan status CANCELLED dari dua terminal POS terpisah dalam satu outlet selama event flash-sale offline.

2. Opsi yang Dipertimbangkan

SEC-02
✕

Opsi A: Last-Write-Wins (LWW) Berdasarkan Client Timestamp

Ditolak

Waktu perangkat lokal rentan terhadap clock drift hingga beberapa menit dan manipulasi manual oleh staf kasir, yang membuka celah pembatalan fiktif setelah transaksi sah selesai.

✕

Opsi B: Centralized Lock via Redis

Ditolak

Gagal memenuhi mandat utama produk: operasional toko harus 100% mandiri saat link fiber optik terputus tanpa latensi remote network lock.

✓

Opsi C: Finite State Machine (FSM) Deterministik

Dipilih & Diterapkan

Menerapkan matriks transisi status yang tidak dapat dibatalkan (asinkron), menjamin idempotensi payload mutasi, dan memvalidasi order versi logis secara monolitik di gateway backend.

3. Keputusan & Skema Implementasi

SEC-03

Implementasi inti ditulis menggunakan bahasa Go pada modul engine/order/statemachine.go dengan pemetaan transisi berikut:

order_state_machine.go 
package orderfsm

type OrderState string

const (
    StateCreated   OrderState = "CREATED"
    StatePaid      OrderState = "PAID"
    StateShipped   OrderState = "SHIPPED"
    StateCancelled OrderState = "CANCELLED"
)

// Valid transitions map: Current State -> Set of Permitted Next States
var AllowedTransitions = map[OrderState][]OrderState{
    StateCreated:   {StatePaid, StateCancelled},
    StatePaid:      {StateShipped},
    StateShipped:   {},
    StateCancelled: {},
}
lightbulb

Prinsip Kritis Arsitektur (Invariant #14)

State CANCELLED bersifat terminal dan absolut. Tidak ada event sinkronisasi offline apa pun yang diizinkan membatalkan status order yang telah dibatalkan di server pusat, guna mencegah komoditas inventori ganda.
